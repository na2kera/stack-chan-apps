# StackChan 自動撮影アプリ MVP仕様書

作成日: 2026-09-30  
対象: M5Stack製 StackChan K151  
対象読者: この会話を読めない実装エージェント

## 1. 目的と完成条件

利用者がStackChanに「写真撮りたい」などと話すと、StackChanが「写真を撮るよ」と返答し、首を少し動かして全員の顔を画面に収める。10秒以内に全員が目を開けて笑顔になった瞬間の写真を選び、写真のダウンロード用QRを表示する。続けて、文言とハッシュタグを入力済みにしたX投稿画面を開く別のQRを表示する。

**MVPの境界:** Jev、会話LLM、X API経由の自動投稿、写真のXへの自動添付は使わない。Xへの実際の投稿と写真添付は利用者自身がスマホで行う。写真はサーバーに一時保存し、期限後に削除する。

## 2. 決定済み要件と実装上の仮定

| 項目 | 仕様 |
| --- | --- |
| ハードウェア | M5Stack StackChan K151。内蔵カメラ、マイク、スピーカー、タッチ画面、X/Y方向サーボ、Wi-Fiを利用する。カメラ最大640×480。画質は実機で評価する。 |
| 起動 | 日本語音声「写真撮りたい」「写真撮って」「撮影して」など。タッチによる代替起動も必須。起動中の重複指示は無視する。 |
| セリフ | 撮影開始時に録音済みの「写真を撮るよ！ いい顔をしてね」を再生する。音声素材はリポジトリで差し替え可能にする。 |
| カウント | セリフ再生後に10秒。1秒ごとに残り時間を表示。手動再撮影で毎回新たな10秒とする。 |
| 首振り | 本体の位置は変えず、首の水平・垂直方向のみ。動作範囲は安全な小角度から設定可能にし、端に達したら止める。 |
| 複数人 | 1人以上。認識された全員の顔が見切れず、全員が目を開け笑顔のときに自動採用。全員の表情条件を満たせない場合は候補写真と「撮り直す」を提示する。 |
| 写真QR | 1枚の写真の専用HTTPSページへ遷移。ページには写真、ダウンロードボタン、削除予定時刻。QRで開ける人ならアクセス可能。 |
| X投稿QR | 写真QRの次の画面。あらかじめ設定した文言とハッシュタグのみを入力済みにしたX投稿画面へ遷移。写真URLは投稿文に含めない。 |
| 一時保存 | 写真の保存期間は撮影から1時間を初期値とする。期限は設定で変更可。期限切れ後は画像とページから写真へアクセスできない。 |

**実装仮定 A:** MVPはK151に書き込む独立した撮影用ファームウェアとして実装する。純正ファームのアプリ一覧に追加するための公開・配布方法は本仕様の対象外。純正機能を残したままアプリ一覧に追加できると仮定しない。実機へ書き込む前に復旧方法をREADMEへ記載する。

**実装仮定 B:** 音声認識とMediaPipeは撮影時に起動しているPC上で実行する。写真配布ページはスマホのモバイル回線からも閲覧できる公開HTTPSサービスで提供する。PCのLANアドレスをQRに入れない。ユーザーのOracleサーバーを使う場合も、HTTPS・稼働時間・一時ファイル削除を満たすこと。写真を受け取るPCと配布サーバーは分離可能にする。

**実装仮定 C:** 一度に最大4人を目標とする（設定値）。上限を超える、顔が端で見切れる、映り込んだ人と被写体を区別できない場合は自動採用せず案内する。人数の意図は画像から完全には分からないため、撮影開始前に全員が画角に入るよう案内する。

## 3. システム構成

1. **device/**: K151用Arduino/C++ファーム。マイク録音、プレビュー用フレーム取得、首振り、セリフ再生、画面表示、タッチ操作、Wi-Fi通信、QR表示。常時待機中は小さな音声チャンクをPCへ送る。
2. **edge/**: PC上のPythonサービス。音声認識（日本語対応のWhisper系）、起動語の正規化と判定、MediaPipe Face Landmarkerによる顔・表情解析、候補フレームの保持、サーボの目標角度計算、10秒撮影セッション、画像配布サーバーへのアップロードを担当。LLMは使わない。
3. **gallery/**: 公開HTTPSサービス。認証されたedgeから写真を受け取り、期限付きの閲覧・ダウンロードページを提供し、期限後に削除する。X投稿用の短いリダイレクトURLも提供する。

データ経路: `StackChan ⇄ (同一LAN) edge → (HTTPS) gallery → (HTTPS QR) スマホ`。X投稿QRは `galleryの短いURL → X Web Intent`。画像フレームは撮影セッション中だけ送信する。外部公開するのはgalleryのみ。

### 技術の初期選択

- Device: Arduino IDE / PlatformIO、M5StackChan・M5Unified、esp_camera、JPEGエンコード、QR描画ライブラリ。ライブラリとボードパッケージのバージョンは実装時に固定する。
- Edge: Python 3.11系、FastAPIまたは同等の非同期HTTP/WebSocketサーバー、MediaPipe Face Landmarker（`num_faces=4`, `output_face_blendshapes=True`）、Whisper系の日本語文字起こし。モデルはアプリ起動時に1回ロードする。PC GPUは必須にしない。
- Gallery: FastAPI等 + 期限付きローカルストレージまたはオブジェクトストレージ。DBなしでも期限情報を永続化できる方式を採る。公開URLと保存期限を設定で変更可能にする。
- HTTPS・ストレージ・開発機の具体的な製品選択は設定で差し替え可能にする。サーバーへの秘密鍵はdeviceに入れない。

## 4. 状態遷移と画面

| 状態 | 入る条件 | 画面・音声 | 終了条件 |
| --- | --- | --- | --- |
| IDLE | 起動直後・終了後 | StackChanの顔と「写真を撮りたい、と言ってね」／タッチ開始 | 音声コマンドかタッチ |
| ANNOUNCE | 起動受理 | 「写真を撮るよ！ いい顔をしてね」再生。マイクを停止 | 音声再生完了 |
| COMPOSE | セリフ終了 | プレビュー。「みんな画面に入ってね」。首を緩やかに調整 | 1秒連続で1人以上の顔が枠内、または5秒経過 |
| CAPTURE | 構図確認後 | 10秒カウント。プレビュー、人数・残り秒数。撮影中も小さな首振り調整 | 成功フレームまたは時間切れ |
| REVIEW | 時間切れで条件未達 | ベスト候補のプレビュー。「保存する」「撮り直す」。候補なしなら「撮り直す」のみ | 選択 |
| UPLOADING | 写真採用 | 「写真を準備中」。重複撮影しない | gallery応答またはエラー |
| PHOTO_QR | アップロード成功 | 「写真を保存」QR、削除時刻、「次へ」「撮り直す」 | タッチで次へ／撮り直し |
| X_QR | 「次へ」 | 「保存した写真をXに添付してね」・投稿用QR・「戻る」「終了」 | タッチ |
| ERROR | 通信・センサー等の失敗 | 理由、再試行／タッチ撮影／終了 | 選択 |

COMPOSEは10秒の外側とする。CAPTURE開始からタイムアウトまでの時間は単調増加時計で測る。サーボが動いている最中のブレたフレームは採用しない。撮影成功時は、その判定に使った**同じフレームのバイト列**を保持して保存する。「撮れたよ」と短く表示し、その後PHOTO_QRへ進む。

音声待機とセリフ再生は排他的にする。再生中はマイクを止め、再生完了後に必要なら待機を再開する。カウント中は音声コマンドを受け付けない。

## 5. 音声起動

- IDLE時に16 kHz/mono/PCM相当の音声を短い区間に切り、LAN上のedgeへ送る。送信量抑制のためVADを使い、無音を捨てる。音声は文字起こし後に破棄し、恒久保存しない。
- Edgeは日本語音声認識し、空白・句読点を正規化して「写真撮って」「写真を撮りたい」「撮影して」「写真撮りたい」などを起動意図として扱う。誤作動防止に認識信頼度・直近3秒の再起動禁止を設定可能にする。判定が不確実なら起動せず、タッチを使える状態にする。
- Deviceが `IDLE` 以外なら起動イベントを無視する。edgeがオフラインの場合は画面で知らせ、タッチ操作は可能にしてエラーの診断に使う。
- 音声コマンドは文字列マッチングを基本にし、自然言語の自由会話は要求しない。音声処理の実装で継続ストリームが難しい場合は、VADで区切った短いクリップをPOSTしてもよい。

## 6. 顔判定・首振り・写真選択

### 6.1 フレーム

- K151内蔵GC0308カメラの実機形式を確認する。公式サンプルはRGB565/QVGAプレビュー。edgeへの送信前にJPEG化する場合は変換可能性とメモリを実機で検証し、失敗時はRGB565の転送を実装する。640×480を配布写真の目標、判定は320×240程度から開始する。
- CAPTUREで目標2フレーム/秒以上。通信・推論が間に合わなければキューを溜めず古い未処理フレームを捨てる。1フレームに`session_id`, `frame_id`, `capture_monotonic_ms`, `servo_x`, `servo_y`, `width`, `height`, `format`を付ける。
- プレビューと判定画像の左右反転や回転が異ならないよう統一する。写真保存はExif等に依存せず、スマホで正立する画像として出す。
- 撮影成功時に別のシャッターを遅れて切らない。高解像度フレームへ切替える場合は同時刻の同じ表情を保証できないため、MVPでは判定に使う保存可能フレームを優先する。

### 6.2 検出と採用条件

- MediaPipe Face Landmarkerの最大顔数を4に設定し、顔ランドマークと表情blendshapeを取得。顔数0または5人以上が疑われるときは自動採用しない。最大4という上限はモデル設定とUIで共通にする。
- 各顔のランドマークから顔の矩形を計算し、フレームの上下左右それぞれ8%の安全余白内に顔矩形全体が入ることを要求する。顔が小さすぎる場合（幅が画像幅の8%未満）は自動採用しない。これらは初期値で、実写で調整可能にする。
- 瞬き判定: `eyeBlinkLeft <= 0.25` かつ `eyeBlinkRight <= 0.25`。笑顔判定: `mouthSmileLeft >= 0.55` かつ `mouthSmileRight >= 0.55`。**全検出顔**が上記を満たす。これらはMediaPipeのスコアに対する**本アプリの暫定閾値**であり、事前に正確性を保証する値ではない。10人程度の実写検証で調整する。
- 人数の一時的な検出落ちで少人数写真を即採用しないよう、COMPOSE終了時の最大顔数を目標人数とし、CAPTURE中に新たに見つかった顔数が増えたら目標人数を増やす。目標人数未満のフレームは自動採用不可。人数は少なくとも1秒（連続2フレーム）安定していること。
- 条件達成が2連続フレームなら**2枚目を採用**。シャッター音を鳴らす場合は判定後に再生する。10秒の終了後に届いた結果は採用しない。
- 笑顔判定は本人の感情・魅力の評価ではない。目と口の見え方に基づく撮影条件として扱う。眼鏡、マスク、横顔、子ども、照明等で誤判定し得るため、撮り直しと手動採用を残す。

### 6.3 首振り

- 最初は正面姿勢に戻す。顔矩形をまとめた外接矩形の中心と画面中心の差を計算し、顔全体の上下左右の余白を見て、収まりやすい方向へ少量動かす。
- モーターの回転方向とカメラ画像の動きの符号は実機で校正する。`image_dx → servo_x`, `image_dy → servo_y`の係数を設定値にし、固定方向をコードに埋め込まない。
- 初期制限は中心からX±25°、Yは25〜65°、1回の指示は最大3°、指示間隔は500 ms以上、速度は低め。実機の可動域と安全性を確認して調整する。公式推奨のY軸5〜85°の範囲を越えない。
- 顔がいないときの首振りは小さい角度を左右に探索し、頻繁な往復を避ける。顔が一部見切れたときだけ外接矩形を使って補正する。首を振っても全員が入らなければ「もう少し寄ってね」と画面と音声で案内する。顔の検出数が変わる間は採用を保留する。

### 6.4 タイムアウト時

- 10秒で成功しなければ、最大人数が写り、見切れず、開眼人数が多く、最低の笑顔スコアが高く、ブレの少ないフレームを優先する。優先順位をコード化し、スコアと採用理由をログに残す。顔ゼロなら候補なし。
- 候補をREVIEW画面で示し、利用者が「この写真を保存」または「撮り直す」をタッチする。基準未達写真を自動公開しない。候補フレームはRAMまたはedgeの一時領域に置き、再撮影・終了時に消す。

## 7. 写真配布とQR

### 7.1 一時保存

- Edgeが採用した画像のみgalleryへ送る。edge→galleryはサーバー間の秘密鍵または署名で認証。デバイスからgalleryへ秘密鍵を送らない。画像以外の解析フレーム・音声はgalleryに残さない。
- `POST /internal/photos` は画像JPEG、撮影時刻、`session_id`を受け、`photo_id`、推測困難な閲覧トークン、`expires_at`、公開HTTPS URLを返す。同じ`session_id`の再送は同じ写真として冪等処理し、重複生成しない。画像サイズ・MIMEを検証する。
- 公開URL例: `https://<public-host>/p/<random-token>`。トークンは少なくとも128ビットの乱数から生成し、逐次IDや端末識別子を含めない。ページは検索エンジンのインデックス対象外、キャッシュ無効、`Referrer-Policy: no-referrer`。アクセスログにフルトークンを記録しない。
- ページにはプレビュー、`写真をダウンロード`ボタン（JPEGのダウンロード）、日本時間での削除時刻を表示。QRを読んだスマホがWi-Fiでもモバイル回線でも開ける。認証なしでURLを知る人が閲覧できる仕様を画面上で示す。
- TTLは初期1時間。バックグラウンド削除ジョブを例えば5分間隔で実行し、期限後はページと画像を直ちに410（または404）にする。削除ジョブ遅延中もアプリ層で期限を判定して配信しない。ダウンロードしても期限を延長しない。
- 削除・再撮影時に古い写真を積極削除できるようにする。再撮影による削除はまだQRを渡していなければ即時、QR提示後ならTTL満了まで保持（利用者が先に読み取った可能性があるため）。

### 7.2 2種類のQR

1. **写真保存QR**: `/p/<random-token>`のHTTPS URL。最初に表示する。スマホに「写真を保存」させる。ダウンロード済みかどうかを端末側で確実には検出できないので、次へ進む操作は利用者のタッチに委ねる。
2. **X投稿QR**: 2枚目の画面。`https://x.com/intent/tweet?text=<URLエンコードした本文>`に遷移する短いHTTPS URL（例`/share/x`）を表示してもよい。本文の初期設定例は `@na2kera_0510 の #ｽﾀｯｸﾁｬﾝ に撮ってもらいました！　#StackChan #STECHFES2026 #STECH`。文言とタグは設定ファイルで変更可。本文に写真URLや写真トークンは含めない。Xの投稿画面を開くだけで、投稿実行は利用者が行う。

画面サイズは320×240。QRを160px以上の正方形で大きく表示し、長いURLで読み取りづらい場合は短いサーバーURLを使う。実機でiPhone/Androidの標準カメラから読み取れることを検証する。投稿QRは写真と独立した共通URLでもよい。

## 8. Device–Edge通信契約（MVP）

実装者はHTTP + WebSocketまたは同等の双方向通信を選んでよいが、**下記のイベントと相関IDを保つこと**。通信仕様の確定版を`docs/protocol.md`に残す。edgeはLAN内でのみlistenし、device IDと共有鍵で接続を確認する。

| 方向 | イベント | 必須項目 | 応答・備考 |
| --- | --- | --- | --- |
| Device→Edge | `hello` | `device_id`, `protocol_version` | `ready`、edge状態 |
| Device→Edge | `audio_clip` | `device_id`, `seq`, `sample_rate`, `pcm_bytes` | IDLE時のみ。edgeは`start_requested`を返せる |
| Device→Edge | `session_start` | `session_id`, `started_at` | edgeは状態を初期化 |
| Device→Edge | `frame` | `session_id`, `frame_id`, `capture_monotonic_ms`, `format`, `width`, `height`, 画像バイト | edgeは`frame_result`を返す |
| Edge→Device | `frame_result` | `session_id`, `frame_id`, `face_count`, `target_face_count`, `all_eyes_open`, `all_smiling`, `servo_target`, `accepted` | 古い`frame_id`は無視。`accepted`なら対応フレームをedgeで保持 |
| Device→Edge | `session_timeout` | `session_id` | edgeは`candidate`または`none`を返す |
| Device→Edge | `review_decision` | `session_id`, `save`/`retake` | 保存時はedgeがアップロード |
| Edge→Device | `photo_ready` | `session_id`, `photo_url`, `expires_at`, `share_url` | 端末がQRを描画 |
| Device→Edge | `session_cancel` | `session_id` | 未公開の候補を破棄 |

`session_id`は端末が生成するUUID。端末とedgeは各状態を持ち、古いセッションの遅延応答を無視。タイムアウトは端末の単調増加時計で決め、edge時計は写真の有効期限に使用。画像送信の失敗で無限再送しない。アップロードだけは同一`session_id`で最大3回再試行できる。PCを再起動した場合は現在の撮影を中止し、利用者に再試行を表示する。

## 9. 設定・ログ・失敗時の動作

- 設定可能な値: Wi-Fi、edgeアドレス、public gallery URL、認証キー、カウント秒数、保存TTL、最大人数、笑顔/瞬き閾値、音声起動語、X本文とタグ、首振り係数・角度上限、フレーム送信間隔。鍵はGitへ入れない。サンプル設定だけコミットする。
- ログには状態遷移、遅延、顔数、判定の真偽、選択したframe_id、サーボ角、写真削除時刻、エラー種別を残す。写真・音声バイトと閲覧トークンを通常ログへ書かない。
- PC/edge不通: 画面で接続待ち、再接続。自動判定付き撮影は開始しない。タッチから診断画面を開ける。
- 顔が検出できない: 10秒終了後「顔が見つからなかったよ」、撮り直しを提示。
- サーボエラー: 安全に停止し、固定カメラで撮影継続可能な場合は続行、復旧不能ならエラー表示。
- galleryへのアップロード失敗: 採用画像をedge側に短時間保持し、再試行。QRを捏造せず、保存できなければエラーと再試行表示。
- 写真QRの期限切れ: スマホには期限切れ表示。StackChan側も期限切れならQRを消す。
- 停電・プロセス再起動: galleryは保存期限を永続化して期限切れ画像を削除する。edgeの未公開フレームは再起動時に破棄する。

## 10. 検証・受け入れ条件

1. K151でプレビュー、音声録音とセリフ再生、首のX/Y制御、Wi-Fi通信、QRの表示を個別に実機確認する。カメラとM5StackChan制御ライブラリの併用、マイク/スピーカー切替を統合検証する。
2. 音声「写真撮りたい」で1回だけ起動し、撮影中は重複起動しない。音声を認識できない場合でもタッチで撮影できる。
3. 1人、2人、4人のパターンで顔数、見切れ、瞬き、笑顔を判定する。誰か1人が目を閉じる/笑わないと自動採用しない。条件を2フレーム連続で満たしたら採用する。5人以上は自動採用しない。
4. 顔の位置を左右・上下にずらすと首が小角度で正しい方向へ動き、端点を超えない。全員が入らない場合は寄るよう案内する。
5. CAPTURE開始後10秒で必ず終了する。条件達成時は採点した同じフレームが保存される。未達時は候補を勝手に公開せず、保存/再撮影の操作を待つ。
6. 写真QRをスマホのWi-Fiとモバイル回線から読み、JPEGを端末に保存できる。期限前は再読込可、期限後は画像を取得できず、保存領域から消える。
7. 2枚目のQRでX投稿画面が開き、指定文言とハッシュタグが入る。写真URL・トークンは本文に入らず、写真は自動添付されない。利用者が保存済み画像を手動添付できる。
8. 動画録画や音声は恒久保存せず、通常ログにも残さない。秘密鍵なしで画像アップロードできない。ランダムでないURLでは写真を列挙できない。

## 11. 実装順・成果物

1. `device/`で独立ファームの起動、タッチ開始、カメラプレビュー、首制御、セリフ、固定QRを通す。
2. `edge/`でフレーム受信、MediaPipeの複数顔判定、構図制御、10秒撮影とレビューを完成させる。ここまではgalleryをモックで置き換え可能。
3. 音声認識で起動する経路を追加し、タッチ開始と同じ状態機械へ接続する。
4. `gallery/`でHTTPS配布、ダウンロード、TTL削除、X Intentの短いリンクを実装し、実機から2種類のQRを読み取る。
5. 端から端まで実写テストし、閾値・サーボ方向・撮影間隔・画質を調整する。

リポジトリには`README.md`（準備・書込み・起動・復旧手順）、`device/`、`edge/`、`gallery/`、`docs/protocol.md`、設定例、最小限の自動テストを含める。ハードウェア無しでもedge判定とgallery期限切れをテストできるよう、録画済みの合成/同意済みサンプル入力とモックを用意する。顔写真の実サンプルは本人の同意なしにコミットしない。

## 12. 根拠・実機で確認する事項

- [M5Stack K151製品資料](https://docs.m5stack.com/en/StackChan): 内蔵GC0308 640×480、320×240画面、ESP32-S3、カメラ・マイク・スピーカー・サーボ・Wi-Fi、Arduino/UiFlow2対応。工場ファームの復旧説明も掲載。
- [M5Stack公式カメラ例](https://docs.m5stack.com/en/arduino/stackchan/camera): RGB565/QVGAでのプレビュー例。JPEG変換と複数機能の同時利用は本アプリ固有の実機確認が必要。
- [M5Stack公式サーボ例](https://docs.m5stack.com/en/arduino/stackchan/servo): `M5StackChan.Motion.move*`、角度単位と可動範囲。
- [M5Stack公式マイク例](https://docs.m5stack.com/en/arduino/stackchan/mic): 録音例とマイク・スピーカーの排他に関する注意。
- [MediaPipe Face Landmarker Python](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python): 複数顔・blendshape・ライブ入力。複数顔時に平滑化が限定される点に注意。
- [Whisper公式リポジトリ](https://github.com/openai/whisper): 日本語を含む多言語文字起こし。
- [X Web Intents公式](https://docs.x.com/x-for-websites/web-intents/overview): 投稿画面を開くWeb Intent。ユーザーの操作で投稿を完成する。

**要実機検証:** 顔を向けた際のX/Yサーボ符号、カメラ画角と最大人数、RGB565からJPEGへの変換負荷、画像送信しながらの音声/画面更新、640×480での品質、QR読み取りサイズ、PCとK151間のLAN通信品質。これらの実測によって設定初期値を調整するが、ユーザー向けフローと受け入れ条件は維持する。
